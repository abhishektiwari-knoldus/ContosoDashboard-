# Contract: File Storage and Scan Services

## IFileStorageService

The business layer depends on a storage abstraction rather than filesystem or cloud APIs.

```text
Task<string> UploadAsync(Stream content, string relativePath, string contentType)
Task<Stream?> DownloadAsync(string relativePath)
Task DeleteAsync(string relativePath)
Task<bool> ExistsAsync(string relativePath)
```

Contract rules:

- `relativePath` is generated by the application and must remain relative to the configured root.
- Implementations must reject path traversal and never concatenate an original user filename into a path.
- Upload must create missing directories and must not overwrite an existing generated path.
- Download must return no data when the path is missing.
- Local storage is rooted outside `wwwroot`; a future Azure adapter maps the same relative names to blob names.
- The service does not perform authorization; callers must authorize the document before invoking download or delete.

## IDocumentScanService

```text
Task<ScanResult> ScanAsync(Stream content, string fileName, string contentType)

ScanResult:
  IsAccepted: boolean
  Reason: string?
  DetectedType: string?
```

Contract rules:

- The scan is mandatory before storage bytes become available.
- The training implementation performs extension allowlist, MIME consistency, size, and basic content-signature checks and returns rejection/quarantine for unsafe input.
- A production implementation must use an approved malware scanner; the local implementation must be labeled training-only in documentation.
- The scan must not persist or disclose rejected content.
